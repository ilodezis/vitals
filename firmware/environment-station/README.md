# Станция среды: прошивка

ESPHome-прошивка для станции в спальне: ESP32-C3 SuperMini Plus и SCD41 (CO₂,
температура, влажность). Станция ничего не знает о Vitals: раз в 10 секунд она
собирает один JSON-снимок и отдаёт его по адресу `GET /text_sensor/env_snapshot`,
а Vitals сам приходит и забирает. Контракт снимка: `docs/ENVIRONMENT_V1_SPRINT.md`, §2.1.

| Файл | Что это |
|---|---|
| `station.yaml` | рабочая прошивка станции |
| `bringup.yaml` | диагностическая прошивка для проверки железа (шина I²C, датчики), в работе не нужна |
| `secrets.example.yaml` | шаблон секретов, лежит в git |
| `secrets.yaml` | настоящие секреты, **в git не попадает** (`.gitignore`) |

## Секреты

```bash
cp secrets.example.yaml secrets.yaml
```

Замени все значения. Что где используется:

| Ключ | Зачем |
|---|---|
| `ap_password` | пароль резервной точки доступа (8–63 символа) |
| `ota_password` | пароль заливки по Wi-Fi |
| `api_key` | ключ шифрования нативного API, нужен только для `esphome logs` по Wi-Fi |

Ключ для `api_key`:

```bash
python -c "import secrets, base64; print(base64.b64encode(secrets.token_bytes(32)).decode())"
```

Пароль Wi-Fi домашней сети в YAML **не пишется**: плата хранит ту сеть, в которую её
однажды ввели (см. ниже). Поэтому пароль от Wi-Fi не попадает ни в репозиторий, ни в бинарник.

## Сборка

Все команды из папки `firmware/environment-station`. Первая сборка занимает 1–5 минут,
последующие быстрее.

```bash
esphome compile station.yaml
```

На Windows, если ESPHome установлен в отдельном venv, запускайте через `<путь-к-venv>\Scripts\esphome.exe`.

## Заливка по Wi-Fi

Работает, пока плата в сети и уже крутится любая прошивка ESPHome (и `bringup.yaml`, и
`station.yaml`). Занимает секунды.

```bash
esphome upload station.yaml --device <адрес-станции>
```

В `--device` годится IP из DHCP-резервации роутера или `environment-station.local`.
Пароль OTA берётся из `secrets.yaml`. Если на плате ещё `bringup.yaml` без пароля OTA,
первая заливка пройдёт без пароля, дальше он обязателен.

Логи по Wi-Fi (нужен `api_key` из секретов):

```bash
esphome logs station.yaml --device <адрес-станции>
```

## Заливка по USB через web.esphome.io

Нужна, если Wi-Fi недоступен совсем или плата не отвечает.

1. Собери прошивку: `esphome compile station.yaml`. Готовый образ для USB лежит в
   `.esphome/build/environment-station/.pioenvs/environment-station/firmware.factory.bin`.
2. Подключи плату кабелем USB-C к компьютеру. Если порт не появился, зажми кнопку BOOT
   на плате, воткни кабель и отпусти кнопку: плата войдёт в режим загрузчика.
3. Открой <https://web.esphome.io> в Chrome или Edge (Firefox не умеет Web Serial).
4. **Connect**, выбери порт платы, затем **Install** и укажи `firmware.factory.bin`.
5. Галку **Erase device** не ставь: она сотрёт сохранённый Wi-Fi, и придётся вводить сеть
   заново (см. следующий раздел).

## Плата потеряла Wi-Fi

Так бывает при смене роутера или пароля, переезде и стёртой памяти. Перезагружать
вручную ничего не нужно:

1. Если плата не может подключиться к сохранённой сети, примерно через полторы минуты она
   сама открывает точку доступа **Environment Station Fallback**. Пароль: `ap_password`
   из `secrets.yaml`.
2. Подключись к ней с телефона или ноутбука. Страница настройки откроется сама (captive
   portal), если нет, зайди на `http://192.168.4.1`.
3. Выбери сеть, введи пароль, сохрани. Плата перезагрузится и подключится.
4. Проверь, что адрес в `VITALS_ENV_STATION_URL` не поменялся. Если у станции новый IP,
   сделай новую DHCP-резервацию на роутере.

Если точка доступа не появилась (память стёрта, прошивки нет): залей `station.yaml` по USB,
как описано выше.

## Проверка работы

Станция отдаёт снимок без авторизации:

```bash
curl http://<адрес-станции>/text_sensor/env_snapshot
```

ESPHome 2026.6 отвечает так (поле `value` содержит JSON-снимок строкой):

```json
{"name_id":"text_sensor/env_snapshot","id":"text_sensor-env_snapshot","value":"{\"v\":1,...}","state":"{\"v\":1,...}"}
```

Клиенту нужно читать **только `value`**. Поле `id` в версии ESPHome 2026.8 сменит формат,
поэтому опираться на него нельзя.

Содержимое снимка (контракт v1):

| Поле | Смысл |
|---|---|
| `v` | версия контракта, сейчас `1` |
| `boot` | случайный идентификатор запуска, меняется при перезагрузке |
| `seq` | номер снимка с начала запуска, сбрасывается при перезагрузке |
| `t` | время от SNTP (epoch, секунды), `0` пока нет синхронизации |
| `up` | секунд с запуска |
| `co2`, `temp`, `rh` | последние значения SCD41, `null`, пока датчик не ответил |
| `lux` | освещённость, `null` без BH1750 |
| `rssi`, `heap`, `fw` | сигнал Wi-Fi (dBm), свободная память (байт), версия прошивки |

Пара `(boot, seq)` однозначно определяет снимок. Снимок обновляется каждые 10 секунд,
датчик меряет раз в 5.

Страница станции с живыми значениями на русском: `http://<адрес-станции>/`. Плата отдаёт её
целиком из прошивки, внешних скриптов и стилей в ней нет.
Она нужна для проверки на месте, основной интерфейс остаётся в Vitals.

## Как включить BH1750 (датчик света)

В v1 датчика нет, место под него оставлено.

1. Подключи BH1750 к той же шине, что и SCD41: SDA на GPIO4, SCL на GPIO3, питание 3,3 В и
   земля. Адрес по умолчанию `0x23` (вывод ADDR не подключён или на земле), `0x5C`, если
   ADDR на питании.
2. В `station.yaml` раскомментируй блок `platform: bh1750` в секции `sensor` и группу
   `grp_light` в `web_server.sorting_groups`.
3. `esphome compile station.yaml`, затем `esphome upload ...`.
4. Поле `lux` в снимке станет числом. Больше ничего править не нужно: блок сам пишет
   значение в глобальную переменную, из которой его берёт снимок.

Датчик смотрит окошком вверх, не на экран и не на окно.

## Что настроить до приёмки

В начале `station.yaml`, секция `substitutions`, значения **предварительные**:

| Параметр | Сейчас | Что делать |
|---|---|---|
| `scd41_temperature_offset` | `4.0` | после двух часов прогрева сверить с бытовым термометром. Знак обратный: чем больше число, тем ниже показание |
| `scd41_asc` | `false` | автокалибровка выключена: без ежедневного проветривания она занижает CO₂. Вместо неё нужна ручная калибровка у открытого окна |
| `scd41_altitude` | `150` | высота над уровнем моря в метрах (барометра на плате нет) |

До калибровки абсолютные цифры CO₂ надо считать ориентиром (точность датчика ±(40 ppm + 5 %)).

## Светодиоды

RGB-светодиод платы (WS2812 на GPIO8) гасится при запуске. Красный индикатор питания
подключён напрямую к 3,3 В и программно не выключается: если мешает ночью, заклей его.

## Что важно не сломать

- **Имя сущности `env_snapshot`** не переводить и не менять: оно часть адреса, который
  опрашивает Vitals. ESPHome ищет сущность по имени, а прежнюю схему по `object_id`
  отключает в версии 2026.7. Сущность не должна быть `internal`, иначе адрес отдаёт 404.
- **Секция `api` с `reboot_timeout: 0s`.** Значение по умолчанию (15 минут) перезагружает плату,
  если к нативному API никто не подключён, а у нас никто не подключается.
- **Авторизации на странице и на снимке нет**, это решение владельца: станция живёт только в
  домашней сети. Порт 80 наружу не пробрасывать. Любое устройство в сети может прочитать
  значения и нажать «Перезагрузить станцию». Заливка прошивки закрыта паролем `ota_password`.
